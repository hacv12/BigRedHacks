# Multi-city data packages

Brisa distributes aggregate historical report grids and real OpenStreetMap walking geometry for the Chicago Loop, Central Manhattan, downtown San Francisco and São Paulo’s Paulista–Centro area. The supported area is the rectangle in each manifest, not the whole named city. `public/data/catalog.json` declares the available packages and default coverage. No package estimates a personal probability of harm or real-time safety.

## Rebuild and source verification

Run `python3 scripts/build_data.py --city chicago`, `--city nyc`, `--city sf`, `--city sao-paulo`, or `--all`; no credentials or third-party Python packages are required. The default remains Chicago for compatibility. `--list` lists configurations; `--config PATH` builds a compatible additional source; `--cache PATH` changes the private cache location; `--refresh` stages a fresh download while preserving the last complete cache if refresh fails. See [ADDING_CITIES.md](ADDING_CITIES.md) for CSV onboarding and configuration details.

For Socrata, the builder requests an exact `count(*)`, fetches up to 100,000 selected rows in one complete response (avoiding an expensive source-ID sort), or larger results in 10,000-row pages ordered by Socrata system `:id`, and verifies returned count equals expected count equals unique nonempty source IDs (SF uses offense-row IDs). It checks the source count again after downloading. This catches truncation, duplicate/omitted page records and changes in result size; Socrata does not offer a transaction spanning these requests, so same-count record revisions during extraction remain possible. The exact predicate, selected fields, query hash and configuration hash are recorded in manifest notes. Source and OSM caches are separately keyed by provenance and query. An incomplete or invalid response never replaces the last complete cache. Raw records and IDs are not shipped in public packages.

All selected snapshots and the resulting catalog validate before publication; each JSON file is replaced atomically. Several filesystem renames are not a transaction: deploy the catalog and all associated package files as one release. Runtime loaders reject mismatching metadata. The manifest includes the actual incident extraction time and OSM source timestamp. OSM is a current snapshot, not reconstructed 2025 access.

The original Chicago cache can be migrated explicitly with `--city chicago --import-legacy-chicago-cache /path/to/legacy/cache`. Migration requires the original package's source URL, occurrence period and exact halo to match; it verifies every source ID/count/date/coordinate, exact reaggregated cells/normalization, and exact walking graph equality to the published baseline. It does not trust arbitrary cache files without this comparison.

## Chicago Loop

Source: [Chicago Crimes—2001 to Present](https://data.cityofchicago.org/Public-Safety/Crimes-2001-to-Present/ijzp-q8t2), using `date >= '2025-01-01T00:00:00' AND date < '2026-01-01T00:00:00'` and `within_box(location, north, west, south, east)` for the exact halo. The source count includes all offense types returned within that halo.

Eligible primary types are `ROBBERY`, `THEFT`, `ASSAULT`, and `BATTERY`; `domestic` must be exactly false. Eligible places are `STREET`, `SIDEWALK`, `PARK PROPERTY`, `LAKEFRONT / WATERFRONT / RIVERBANK`, `BRIDGE`, and `CTA BUS STOP`. Missing domestic or place flags fail eligibility. Residences, businesses, transit interiors/platforms and alleys are excluded. Broad Chicago theft still includes different circumstances than NYPD's selected person-theft subtypes; the two package indices must not be compared as equivalent crime rates.

Planning bounds are `[-87.644, 41.866, -87.617, 41.891]`; reference latitude is 41.88°. The verified baseline is preserved: 21,349 source reports, 3,064 eligible, 270 grid cells, 21,232 graph nodes and 25,669 edges; Q = 28.85286935286935. Exclusions are 8,576 other-category, 752 domestic/missing-domestic and 8,957 other/missing-place. Occurrence timestamps use America/Chicago local wall time.

## NYC Central Manhattan

Source: [NYPD Complaint Data Historic](https://data.cityofnewyork.us/Public-Safety/NYPD-Complaint-Data-Historic/qgea-i56i). Official metadata was updated April 28, 2026 and includes reports through December 31, 2025. The query selects occurrence starts in calendar 2025 (`cmplnt_fr_dt`), with no extra report-year restriction, and the complete geographic halo. Later-reported occurrences can be absent from the historic release. The [current-year source](https://data.cityofnewyork.us/Public-Safety/NYPD-Complaint-Data-Current-Year-To-Date-/5uac-w243) covers incomplete 2026 quarters and is not mixed into this completed-year package.

Planning bounds are `[-74.020, 40.700, -73.965, 40.780]`, extending from Battery Park through Columbus Circle. They cover parts of Manhattan, not all Manhattan or NYC. Coordinates within the rectangular halo may include nearby land across the river; those reports contribute only through the disclosed grid and smoothing model. The graph retains its largest connected walking component inside the planning rectangle.

The bundled NYC package contains 90,116 unique source reports and 5,497 eligible reports, 1,050 cells, 73,021 graph nodes and 91,746 edges. Q is 17.612650829562593. First-match exclusions are 65,083 other-category records, 10,443 disallowed theft subtypes, 8,760 other/missing premises, 256 cross-bucket occurrence intervals, 75 incomplete intervals, and 2 scalar-coordinate points just outside the halo despite the source geospatial predicate. Every eligible report has a valid local time. The nine landmark snap distances range from 4.2 m to 55.6 m; exact values are in manifest notes. The package is approximately 22.2 MB of uncompressed JSON.

The NYPD API schema uses persistent text `cmplnt_num`, calendar-date `cmplnt_fr_dt`/`cmplnt_to_dt`/`rpt_dt`, separate text `cmplnt_fr_tm`/`cmplnt_to_tm`, numeric `ky_cd` and `pd_cd`, `ofns_desc`/`pd_desc`, `prem_typ_desc`/`loc_of_occur_desc`, and numeric WGS84 `latitude`/`longitude`. Multiple-offense complaints are classified by their most serious offense, so the file is not a count of every offense within a complaint. Attempts are included; attempted murder is recorded as felony assault.

Eligible premises are exactly `STREET` and `PARK/PLAYGROUND`. Eligible categories are robbery (`105`), felony assault (`106`), assault 3 and related offenses (`344`), and grand larceny (`109`) **only** for person-theft internal codes `404` (electronic device snatch), `406` (bag dip), `408` (sleeping/unconscious victim), `414` (neck chain), `415` (pickpocket), `417` (purse snatch) and `419` (other from-person). Vehicle, bicycle, unattended-property, fraud, retail and generic theft codes are excluded. This is an explicit source-specific relevance choice; Chicago's taxonomy differs. There is no domestic/stranger relationship flag in this NYPD source, so the package cannot exclude domestic incidents or identify random encounters solely from an outdoor premise.

A single From datetime is treated as the reported occurrence time in America/New_York. If either To field exists, both must be present and valid; the end cannot precede the start. An interval is counted only if both endpoints share the same local date and six-hour bucket. Cross-bucket, incomplete or reversed intervals are excluded instead of assigning an uncertain start hour as an exact time. Malformed timestamps and nonexistent spring-forward civil times are excluded; repeated autumn hours remain in the same bucket. Counts by exclusion rule appear in the manifest.

The [official NYPD footnotes](https://data.cityofnewyork.us/api/views/qgea-i56i/files/b21ec89f-4d7b-494e-b2e9-f69ae7f4c228?download=true) materially limit spatial interpretation. Locations are approximate street/intersection positions. Rape and sex offenses are placed at precinct station houses and excluded from this model. Other un-geocodable complaints can also use station-house fallback points; there is no reliable fallback flag in these rows, so residual station clustering is a known limitation. Park/beach reports may be located on bordering streets. Do not infer exact addresses, exact incident points or individual people from the aggregate index.

## San Francisco Downtown

Source: [SFPD Incident Reports: 2018 to Present](https://data.sf.gov/Public-Safety/Police-Department-Incident-Reports-2018-to-Present/wg3w-h783). Calendar 2025 occurrences in `America/Los_Angeles`, planning bounds `[-122.426, 37.773, -122.389, 37.803]`, cover a downtown rectangle including Civic Center, Union Square, Chinatown and the Embarcadero. This is a **street/public-place robbery-only package**, a narrower taxonomy than Chicago or NYC.

The complete halo query fetched 48,533 unique `row_id` offense rows and verified the same count before and after extraction. Of those, 160 initial reports qualify; 48,341 rows have other offense codes and 32 are non-initial reports. Eligible six-hour bucket totals are 39, 20, 43 and 58. There are 400 cells, 22,819 graph nodes and 29,178 edges; Q = 1.9378881987577639. Seven public landmarks snap between 4.7 m and 18.4 m from their configured locations. The package is approximately 7.1 MB uncompressed.

The publisher's [incident-code crosswalk](https://data.sf.gov/Public-Safety/Reference-Police-Department-Incident-Code-Crosswal/ci9u-8awy) distinguishes Street or Public Place robbery (`03011`–`03014`) and its attempts (`03411`–`03414`) from generic, commercial, residential and vehicle robbery. Only those eight exact codes qualify. The source has **no premises column**: the adapter derives a place label only from these explicit offense codes. “Public place” does not guarantee outdoors, and neither a pedestrian victim nor a stranger encounter is established. Generic theft and robbery are excluded; this conservative selection is sparse and omits many potentially relevant reports.

Per the [official dataset explainer](https://sfdigitalservices.gitbook.io/dataset-explainers/sfpd-incident-report-2018-to-present), multiple offense rows can share one `incident_id`. Only `report_type_code=II` (Initial) qualifies and each eligible `incident_id` contributes once. The manifest's `sourceReportCount` is therefore a **source offense-row count**, while `eligibleReportCount` is a distinct eligible incident-report count. Additional eligible rows are counted as exclusions. Initial reports can omit later supplemental corrections. Use `incident_datetime`, never filing time; the release has no occurrence-end field, so underlying time uncertainty cannot be resolved.

[Current publisher metadata](https://data.sf.gov/api/views/wg3w-h783.json) says locations are displaced to privacy-approved intersections and describes a mapping change on April 24, 2024. Intersections are not evidence that an incident occurred on the street. Juvenile/confidential reports and some other records are withheld; publication requires supervisory approval, so omissions and delays remain. SF publishes under the Open Data Commons Public Domain Dedication and License. No exact addresses, incident locations or personal risk should be inferred from the aggregate grid.

## São Paulo Paulista–Centro

Source: Secretaria da Segurança Pública do Estado de São Paulo, [official download index](https://www.ssp.sp.gov.br/estatistica/consultas) and [CelularesSubtraidos_2025.xlsx](https://www.ssp.sp.gov.br/assets/estatistica/transparencia/baseDados/celularesSub/CelularesSubtraidos_2025.xlsx). The workbook's `METODOLOGIA` and `DICIONARIO DE DADOS` sheets are the authoritative counting and field definitions. This is an exploratory raw release, not the state's official crime statistics.

The rectangle `[-46.672, -23.575, -46.629, -23.535]` connects Avenida Paulista with parts of the central area; it is not citywide. Calendar 2025 occurrence dates use `America/Sao_Paulo`. The source is a 2025 registration-year workbook, so later-reported 2025 occurrences may be absent. The package has 2,466 eligible reports, 576 cells, 29,861 OSM nodes and 35,551 edges; Q = 10.753884046987494. Time-bucket counts are 391, 429, 829 and 817. Seven landmark access points snap within 44.0 m. The default pair is Edifício Copan → Praça da Sé. MASP is explicitly pinned to reviewed surface-sidewalk OSM node `11285331454`, on concrete sidewalk way `1217933412` adjoining marked crossing `226414787`; a closer two-dimensional point in the Nove de Julho tunnel is not used. The label identifies a Paulista sidewalk, not a museum entrance. The other six access nodes were also checked for tunnel/layer conflicts in this snapshot. Uncompressed JSON is approximately 9.0 MB.

**Eligibility is explicitly pedestrian-related.** Include only `Roubo (art. 157)` or `Furto (art. 155)` with `DESCR_CONDUTA=Transeunte`. Require place group `Via Pública` or `Lazer e Recreação`, and subtype `Via Pública`, `Transeunte`, `Praça` or `Parque/Bosque/Horto/Reserva`. Generic `Outros` conduct, vehicle/transit interiors, businesses and residences do not qualify. The phone-focused source omits incidents without phones; it does not establish a stranger relationship or measure personal risk.

The complete 108,119,158-byte workbook contains 383,635 physical data rows and 309,326 distinct publisher report keys. Its methodology specifies `NOME_DELEGACIA + ANO_BO + NUM_BO`: rows can repeat because of linked objects, people and offense classifications. The importer groups by that exact composite identity, retains the highest numeric `VERSAO`, and counts each eligible report once. It ignores phone quantities and all demographic fields. Conflicting date/time/location values within the latest version cause exclusion. It validates physical row continuity against the worksheet dimension and records a SHA256 of the complete workbook. No arbitrary row cap or initial-page sample is used.

After latest-version consolidation, 32,552 distinct reports have a coordinate in the full incident halo; 276,774 are outside or unlocated. The former is `sourceReportCount`. First-match exclusions within the halo are 19,217 missing/imprecise timestamps, 80 conflicting latest-version occurrence fields, 5 source-city/coordinate mismatches, 10,408 other category/conduct, 305 other places, 38 other place subtypes and 33 occurrences outside 2025. These leave 2,466 eligible reports. Unlocated statewide reports are outside the spatial extract, so `missingCoordinateCount` is not a statewide missing-data measure.

`DATA_OCORRENCIA_BO` and `HORA_OCORRENCIA` are Excel date/time values interpreted as local civil time. A missing hour or any broad `DESCR_PERIODO` label is excluded rather than imputed to midnight. An explicitly recorded numeric zero hour remains midnight. This substantially reduces the source and can introduce time-reporting bias; no claim is made that the retained records represent all incidents. `CIDADE` must be `S.PAULO` even when coordinates fall inside coverage. Coordinates can contain geocoding errors and are not verified incident points. The publisher suppresses protected locations; Brisa distributes no addresses, personal characteristics, phone details or report IDs. Preserve SSP-SP attribution when reusing these derived aggregates.

Workbook SHA256: `b86cc5576688bff2aa0b65a244c9a396d5e49e9c4eaf05b4e4dd665f1c2956c9`. The query notes record this checksum, complete workbook/report counts, source URL, exact halo and deduplication rules. The private workbook cache has URL/checksum provenance; downloads and parsing finish before a valid source cache is replaced.

## Other LATAM source assessment

São Paulo is the first published LATAM package. Other researched sources were not forced into the same model:

- [CDMX FGJ](https://www.datos.cdmx.gob.mx/es/dataset/carpetas-de-investigacion-fgj-de-la-ciudad-de-mexico): catalog API and official archive CSV timed out; no actual file could be verified.
- [Buenos Aires 2025](https://data.buenosaires.gob.ar/fa_IR/dataset/delitos/resource/66c0f0f6-e682-403d-abbe-47227d1966fe): publisher rejected the download, documented schema lacks premises, and the catalog notes corrections to its executive report.
- [Medellín MEData](https://medata.app.medellin.gov.co/node/16764): accessible CSV has occurrence timestamps, coordinates and public-street/walking fields. However, it lacks a persistent report ID and the `CASO` marker described by its dictionary for separating cases from goods/person records. `cantidad` is a quantity, not a demonstrated report count. Do not invent report identities or treat every object row as an incident.
- [Uruguay microdata dictionary](https://catalogodatos.gub.uy/dataset/999f2edc-5ef5-4d41-bed7-824a5635ea8d/resource/13285391-71b7-4cf3-bec8-26031275aca4/download/metadatos_otrosdelitos.json): supplies dates, hours and event IDs but only department, police jurisdiction and Montevideo neighborhood, not incident coordinates. Neighborhood centroids cannot stand in for real incident positions.
- Bogotá's researched official ArcGIS endpoint timed out. These are findings from this build, not claims that these sources can never support another model or future release.

## Aggregation shared across packages

A local equirectangular grid uses 111,320 meters per latitude degree and 111,320 × cos(reference latitude) per longitude degree. Cells are nominally 250 m square. Three cells (750 m) are added on every side; east/north rounding adds a little more. Source spatial predicates exclude unlocated records, so `missingCoordinateCount` describes returned rows only, not all missing locations in a city. All halo cells are distributed, including zeros; only aggregate counts and four six-hour values are shipped, never incident records, IDs, addresses or incident points.

Exclusions use the first matching rule: missing ID, duplicate ID (CSV), missing/invalid coordinates, outside halo, other category, disallowed subtype, domestic flag (Chicago), missing/other place, invalid/out-of-period timestamp, and invalid or cross-bucket interval (NYC). SF additionally rejects non-initial reports and missing incident IDs, then deduplicates eligible offense rows by incident ID. SSP-SP first consolidates publisher report IDs/versions; its conflicting or imprecise occurrence fields fail before category/place eligibility. Every included report has weight 1. Each manifest's eligible + excluded count equals its source count.

For total N and bucket count S_b, `a=N/(N+20)` and raw activity is `a*4*S_b+(1-a)*N`. Smooth with center weight 0.5 and four cardinal-neighbor weights 0.125. At the outer halo only, renormalize available weights; planning locations have full surrounding support. Q is the larger of 1 and the nearest-rank 90th percentile of positive smoothed values across every halo cell and time bucket. Intensity is `activity/(activity+Q)`. Each package computes its own Q, fixed across its routes and time buckets. Percent reductions compare routes within the same package/time context, not cities against each other. No pedestrian footfall/exposure denominator is available; zeros never establish safety.

## Walking graph and validation

[OpenStreetMap contributors](https://www.openstreetmap.org/copyright), ODbL 1.0, supply walking ways via Overpass `way["highway"](south,west,north,east);out geom;`. Permitted classes are footway, pedestrian, path, steps, living_street, residential, service, unclassified, tertiary/secondary/primary and their links. Reject private/no/customers/delivery/permit/destination access or foot tags, `foot=use_sidepath`, alleys, area polygons, indoor and construction ways. Vehicle one-way restrictions are ignored; explicit `oneway:foot` is honored. Edges are actual consecutive OSM node segments, with both endpoints inside planning bounds. Retain the largest undirected component; routing checks directed reachability separately.

This is a way-tag filter, not an audit of legal crossings, sidewalk quality, stairs, accessibility, closures, grade separation or node-level barrier tags. Landmarks are verified nearby graph points within 75 m of the configured public location, not guaranteed entrances. Preserve attribution when showing derived data.

`python3 scripts/test_data.py` recomputes all package normalizations, validates aggregate counts/coverage/catalog metadata and real graph geometry/connectivity, checks API count and ID completeness, failed-refresh cache preservation, NYPD time interval/subtype exclusions, SF place-coded offense/initial-report/deduplication rules, SSP-SP versioned report identities and exact Excel occurrence-time rules, reviewed OSM landmark pins, civil-time parsing, and synthetic CSV onboarding. No network is used by tests.

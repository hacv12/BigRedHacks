# Chicago Loop snapshot

Run `python3 scripts/build_data.py` with public internet access to rebuild `public/data/chicago-loop.json`; no credentials or third-party Python packages are needed. Then run `python3 scripts/test_data.py`. The script caches downloaded source responses in the ignored repository directory `.data-cache`; use `--refresh` to retrieve a fresh snapshot, or `--cache /path/to/new-empty-directory` for a separate cache. `--osm-file` accepts a previously downloaded Overpass response for the **same planning rectangle**. Source databases can revise records, so fresh downloads need not reproduce identical counts. The bundled manifest records the incident response file modification time (preserved when cached) and OSM timestamps. HTTP downloads are first parsed in a temporary file and atomically replace the cache only on success, so interrupted or malformed downloads cannot become trusted cache entries. Raw source cache files are never bundled.

## Sources and completeness

Chicago's official [Crimes—2001 to Present dataset](https://data.cityofchicago.org/Public-Safety/Crimes-2001-to-Present/ijzp-q8t2) supplies occurrence records. The SoQL predicate selects `date >= '2025-01-01T00:00:00' AND date < '2026-01-01T00:00:00'` and `within_box(location, north, west, south, east)` using the exact incident bounds in the manifest. The script first requests `count(*)` with that predicate, then every matching record ordered by `id` in pages of 50,000. It asserts source count equals fetched count equals unique IDs before aggregation. IDs are used only for deduplication checks and never appear in the output.

The source count covers **all offense categories in the geographic halo**, not all Chicago. Since a spatial query cannot locate missing-coordinate records, the manifest's missing-coordinate count describes returned rows only. Unlocated citywide reports cannot be assigned to this bounded area and are outside this count. Source locations are approximate and reported incidents are not a complete record of harmful events.

Eligible records must have coordinates, a primary type of `ROBBERY`, `THEFT`, `ASSAULT`, or `BATTERY`, `domestic=false`, and an exact location description of `STREET`, `SIDEWALK`, `PARK PROPERTY`, `LAKEFRONT / WATERFRONT / RIVERBANK`, `BRIDGE`, or `CTA BUS STOP`. Every eligible offense has weight 1. Other locations, including residences, businesses, transit interiors/platforms and alleys, are excluded. Park, waterfront, bridge and curbside bus-stop reports are included because the graph permits walking through these outdoor contexts. The source place category is broader than an individual path, so this improves context alignment without establishing exact route-level relevance. The filter is deliberately narrow and does not imply that excluded reports are unimportant. Exclusions are counted by the first matching rule, in that order, followed by missing occurrence date. Missing/other place and domestic flags fail eligibility. The source's occurrence date is interpreted as America/Chicago wall time; its hour directly selects midnight–6, 6–noon, noon–18, or 18–midnight. Daylight-saving repetitions stay in the same six-hour bucket.

## Aggregation and model

The planning rectangle is `[-87.644, 41.866, -87.617, 41.891]` in west/south/east/north order. A local equirectangular grid uses 111,320 meters per latitude degree and 111,320 × cos(41.88°) per longitude degree. Cells are approximately 250 m square. Three whole cells (750 m) are added on each side; rounding the east/north coverage to whole cells adds a little more. Every halo cell is included, even when its count is zero. Only cell totals and four six-hour counts are distributed: no individual reports, addresses, cases or exact incident points.

For count N and equal-weight sums S and S_b, `a=N/(N+20)` and raw activity is `a*4*S_b+(1-a)*S`. Smooth with a cross kernel: center weight 0.5, each of four adjacent cells 0.125. This limits smoothing to neighboring cell centers 250 m away. At the outermost halo only, available kernel weights are renormalized. All planning locations have full surrounding coverage. Set Q to the larger of 1 and the nearest-rank 90th percentile of positive smoothed values across every halo cell and all four buckets. Intensity is `activity/(activity+Q)`; Q is fixed for every route and bucket in this snapshot.

The index is a heuristic of historical reported activity. It is not a personal probability of harm, and it has no footfall/exposure denominator. Zero reports never means safe. Offense selection, equal weighting, cell size, prior and smoothing require sensitivity analysis before broader use.

## Walking graph

[OpenStreetMap contributors](https://www.openstreetmap.org/copyright), ODbL 1.0, supply the graph via a POST to `https://overpass-api.de/api/interpreter` with `[out:json][timeout:120];way["highway"](41.866,-87.644,41.891,-87.617);out geom;`. The response's `timestamp_osm_base` is preserved. OSM data is a separate current snapshot, not a reconstruction of 2025 street access.

Permitted highway classes are footway, pedestrian, path, steps, living_street, residential, service, unclassified, tertiary, tertiary_link, secondary, secondary_link, primary and primary_link. The builder excludes motorways, trunks, cycleways, construction and other classes. It rejects access or foot tags of no/private/customers/delivery/permit/destination, plus foot=use_sidepath, service=alley, names containing alley, area=yes, indoor=yes and construction tags. It ignores motor-vehicle one-way restrictions; explicit oneway:foot=yes/1/true/-1 controls walking direction. Every edge joins consecutive source OSM nodes using their actual two-point segment, retaining OSM node and way identifiers. Both endpoints must lie within planning bounds. The largest undirected connected component is kept; directed routing still checks reachability. This is a street access-tag filter, not an audit of legal crossings, sidewalk quality, stairs, wheelchair access, closures or grade separation. The way-geometry query does not retrieve node-level barrier/access tags, so those restrictions are not audited.

Landmarks denote nearby graph access points, not building entrances or interior destinations. Route geometry should always show the snapped endpoints. The app rejects endpoint snaps over 75 m. Attribution must remain visible when displaying these derived street data.

## Bundled snapshot validation

The snapshot contains 21,349 unique source records, of which 3,064 qualify. First-match exclusions are 8,576 other-category records, 752 domestic/missing-domestic records, and 8,957 other/missing-place records. Returned rows have no missing coordinates or dates; no invalid eligible timestamps were encountered. The graph contains 21,232 nodes and 25,669 edges; the 270 cells include complete zero-count coverage. The normalization Q is 28.85286935286935. Per-landmark access-point snap distances and source way exclusions are recorded in manifest notes.

Filter revision v2 adds 130 park, 30 waterfront/riverbank, 11 bridge and 24 curbside bus-stop reports from the same verified source download (195 total). The original source count and OSM graph remain unchanged. Integrity tests recompute smoothing/normalization from bundled counts and check that malformed downloads preserve an existing valid cache.

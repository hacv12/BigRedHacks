# Address and place search

From/To accept names, addresses and places within the loaded walking coverage. The app first searches bundled landmarks and named street references. Those local suggestions work without an external geocoder. Street references identify a graph section, not an address or entrance.

After the user types at least three characters and pauses for 500 ms while editing, the app queries its configured Photon-compatible provider, defaulting to [Photon's public demo API](https://photon.komoot.io/). The request includes the typed query and the coverage bounding box, not the other endpoint or a device location. Provider logs may retain requests; the app does not claim searches are private or unlogged. Default-provider attribution is **Search by Photon · © OpenStreetMap contributors**, linking Photon and [OSM copyright/ODbL](https://www.openstreetmap.org/copyright). Photon software is Apache-2.0; that is distinct from the OSM database license.

[Photon's official policy](https://github.com/komoot/photon#demo-server) permits reasonable project usage and search-as-you-type, but supplies no availability guarantee and may throttle or ban excessive traffic. No numerical provider quota is promised. We add a shared 750 ms request-start interval, request six results, cancel superseded work, and use a bounded five-minute in-memory cache (40 queries). There are no keys, persistent query storage or bulk geocoding. A production deployment with significant traffic needs a hosted/self-hosted provider and reviewed capacity/privacy terms. [API documentation](https://github.com/komoot/photon/blob/master/docs/api-v1.md) defines bbox as minLon,minLat,maxLon,maxLat. Public Nominatim is not used: its [policy forbids autocomplete](https://operations.osmfoundation.org/policies/nominatim/).

Results are bounded both in the request and again after parsing. Out-of-bounds, malformed or duplicate features are discarded. Address queries containing numbers prioritize provider results; other queries show local matches first. Labels include available house number, street, district and city to disambiguate places. Search completeness is not guaranteed: an empty response does not prove an address does not exist. HTTP errors, invalid responses and the 12-second timeout show a recoverable search failure while local matches remain usable. City/query changes cancel obsolete requests and cannot display previous-area suggestions.

A geocoded coordinate is an approximate place, not a verified accessible entrance. Selecting it still goes through the planner's normal coverage, graph connectivity and maximum snapping-distance validation; geocoding never extends routing coverage. There is no route request for unsupported coordinates. The map remains an optional way to adjust a selection.

Verification on October 3, 2026: a bounded public-landmark address query to Photon returned HTTP200, GeoJSON FeatureCollection with the documented address fields, and Access-Control-Allow-Origin: * for a localhost Origin. Recheck deployed-origin browser access and availability after publication. Local unit tests cover bounds/schema validation, query minimum, deduplication, cache isolation/expiry, cancellation, rate pacing, timeout and provider errors. No fallback fabricates addresses when the network fails.


## Deploying a different provider

Set `VITE_GEOCODER_URL` to the complete Photon-compatible API endpoint, for example `https://search.example.com/photon/api/`, then rebuild. It must implement Photon bbox/query/limit parameters and the same OSM-based GeoJSON response schema. This is not a generic adapter for unrelated commercial geocoders. Review the chosen host's terms, capacity, privacy, CORS and any additional attribution requirements before deployment; only the default Photon host was live-verified here.

HTTPS is required. HTTP loopback (`localhost`, `127.0.0.1`, `[::1]`) is permitted only in Vite development. Credentials, query strings and fragments in the configured URL are rejected; do not put secrets in `VITE_` configuration. Invalid configuration disables remote lookup with an explicit error while local search remains available, rather than silently sending queries to Photon. Custom-provider popup attribution/disclosure identifies the configured host and retains OSM data attribution. Configuration changes do not remove the existing request pacing, limits, cache or cancellation safeguards.

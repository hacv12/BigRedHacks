# Recent reports and dispatch calls

This overlay is separate from the historical route index. It does not measure present danger, confirm an emergency, or change route weights. Official records can be incomplete, revised or removed. Bubbles represent selected reports/calls, not all events or unique victims.

## Verified feeds

- **San Francisco:** [official dispatch dataset](https://data.sf.gov/Public-Safety/Law-Enforcement-Dispatched-Calls-for-Service-Real-/gnap-fj3t), [publisher explanation](https://sfdigitalservices.gitbook.io/dataset-explainers/law-enforcement-dispatched-calls-for-service). Updated every ten minutes with an additional ten-minute delay. Rolling 48-hour published feed can also retain older open calls, so the adapter explicitly filters receipt time. Calls are unverified; multiple dispatch records may describe one event. Locations are anonymized to nearby intersections. Only Police agency, explicitly non-sensitive calls, and type codes 211/212/216/217/219/240/245/418 qualify (robbery, strongarm robbery, shots fired, shooting, stabbing, assault/battery, aggravated assault, fight without weapon). These types do not establish an outdoor incident. Suspicious-person, homelessness and welfare/mental-health complaints are excluded.
- **New York:** [YTD complaint dataset](https://data.cityofnewyork.us/d/5uac-w243), [NYPD quarterly publication explanation](https://www.nyc.gov/site/nypd/stats/crime-statistics/citywide-crime-stats.page). Quarterly releases can lag months. Street/park premises and the same offense/subtype allowlist as the historical package qualify. Occurrence date and exact time are required. No domestic/stranger relationship is inferred.
- **Chicago:** [official incident dataset](https://data.cityofchicago.org/d/ijzp-q8t2). Updated daily but omits the most recent seven days; actual lag can be longer. Requires domestic=false and existing historical offense/public-premise allowlists. Coordinates are approximate block locations. Occurrence time can be a best estimate; updated_on means record modification, not report or publication time.
- **São Paulo:** [official download index](https://www.ssp.sp.gov.br/estatistica/consultas) provides annual workbooks; no verified recent API is implemented. Absence of an overlay does not mean absence of incidents.

Read-only probes on 2026-10-03 at approximately 14:15 UTC: NYC latest global occurrence/report was June 30 (metadata updated July 27); Chicago Loop newest occurrence was September 24; SF downtown confirmed incident reports reached October 1. SF dispatch API had 3,881 distinct CAD identifiers, latest receipt October 3 06:51 Pacific, portal load 07:10 Pacific. A selected downtown 48-hour query yielded 135 calls. These are verification observations, not pinned UI counts. The São Paulo 2026 workbook answered HTTP200, 64.66 MB, Last-Modified September 28; that header does not establish occurrence coverage or publication cadence.

## Query and timestamp contract

Only three hardcoded official HTTPS endpoints are used. Requests omit credentials and referrers. No addresses, people, dispatcher notes or raw narrative fields are requested. Source IDs and approximate coordinates remain transient inputs to aggregation. SF deduplicates cad_number, NYC cmplnt_num, Chicago id; this cannot deduplicate distinct police records concerning the same real event.

NYC/Chicago first query the global maximum nonfuture occurrence date, then fetch the last 30 calendar days ending on that source date, clipped to the current source-local time. Thus NYC may legitimately display a June window in October. SF uses the preceding 48 elapsed hours, expressed in America/Los_Angeles civil timestamps. Offset-free source timestamps are validated and must never be interpreted using the viewer's timezone. Around daylight-saving folds the source's ambiguous civil timestamps cannot distinguish repeated clock hours.

Every row is revalidated for eligibility, timestamp, bounds, ID and coordinates after the bounded server query. Future and malformed rows are excluded. Responses at the 5,000-row cap fail closed instead of displaying incomplete counts. A 25-second abort timeout and caller cancellation apply across requests. Latest available occurrence is queried separately from the requested area; it is not proof of complete coverage. checkedAt is fetch-check UTC, not publication time. Optional publisherUpdatedAt comes from a valid nonfuture official HTTP Last-Modified header, expressed in UTC; it is absent when the header is unavailable or invalid. Conflicting duplicate IDs fail the entire refresh before eligibility filtering; exact duplicates collapse. Optional report, update and closure timestamps must be valid and nonfuture. Event labels distinguish “Call received” from “Occurred.”

UI owns scheduling and cached results, with no polling faster than ten minutes. A failed refresh must retain an explicit stale/error state rather than imply current or empty coverage. Never silently substitute fixture data after a source failure. Both source lag and the displayed window should remain visible.

CORS verification: All three implemented Socrata endpoints answered HTTP200 with Access-Control-Allow-Origin: * for a localhost Origin during read-only aggregate probes on October 3, 2026. Recheck browser access when deploying, since publisher behavior can change.
